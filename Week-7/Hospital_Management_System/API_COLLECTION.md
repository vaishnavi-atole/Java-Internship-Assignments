# API Collection

Base URL: `http://localhost:8080`

For protected APIs, send the token after login in this header:

```text
Authorization: Bearer <token>
```

Most APIs return data in this format:

```json
{
  "status": true,
  "message": "Request completed",
  "data": {},
  "timestamp": "2026-07-12T10:00:00Z"
}
```

## Login

### Login user

`POST /api/auth/login`

```json
{
  "username": "admin",
  "password": "admin123"
}
```

When login is successful, the API sends back a JWT token and the user role. Use that token for the remaining APIs.

Status: `200` for success, `401` for invalid credentials.

### Check login

`GET /api/auth/me`

This is a simple endpoint used to check authentication availability.

## Departments

| API | Method | Who can use it | Purpose |
| --- | --- | --- | --- |
| `/api/departments` | GET | Admin, Doctor, Receptionist | Get all departments |
| `/api/departments/{id}` | GET | Admin, Doctor, Receptionist | Get one department |
| `/api/departments` | POST | Admin | Add a department |
| `/api/departments/{id}` | PUT | Admin | Edit a department |
| `/api/departments/{id}` | DELETE | Admin | Remove a department |

Example for add/edit:

```json
{
  "name": "Cardiology",
  "description": "Heart care department",
  "departmentHead": "Dr. Rao",
  "active": true
}
```

```json
  "active": true
```


## Appointments

| API | Method | Who can use it | Purpose |
| --- | --- | --- | --- |
| `/api/appointments` | GET | All logged-in roles | View appointments |
| `/api/appointments/{id}` | GET | All logged-in roles | View one appointment |
| `/api/appointments` | POST | Admin, Receptionist | Book appointment |
| `/api/appointments/{id}` | PUT | Admin, Doctor, Receptionist | Update appointment |
| `/api/appointments/{id}/completion` | PATCH | Doctor | Mark checkup completed |
| `/api/appointments/{id}` | DELETE | Admin, Receptionist | Cancel appointment |

```json
{
  "doctorId": 3,
  "patientId": 1,
  "appointmentDate": "2026-07-17",
  "appointmentTime": "10:00",
  "reason": "Checkup",
  "status": "SCHEDULED"
}
```

The system blocks past dates and does not allow the same doctor to be booked twice at the same time.

## Billing

| API | Method | Who can use it | Purpose |
| --- | --- | --- | --- |
| `/api/bills` | GET | Admin, Receptionist | View bills |
| `/api/bills/{id}` | GET | Admin, Receptionist | View one bill |
| `/api/bills` | POST | Receptionist | Create bill |
| `/api/bills/{id}` | PUT | Receptionist | Update charges or mark paid/pending |

```json
{
  "patientId": 1,
  "consultationFee": 550,
  "medicineFee": 100,
  "labFee": 0,
  "discount": 0,
  "gst": 30,
  "paymentStatus": "PENDING"
}
```

The server calculates the final amount. Bill deletion is currently disabled by API security.

## Reports and Dashboard

| API | Method | Who can use it | Purpose |
| --- | --- | --- | --- |
| `/api/reports` | GET | Admin, Doctor | Get report data |
| `/api/dashboard` | GET | Admin, Doctor, Receptionist | Get dashboard counts and chart data |

The reports response contains patient, doctor, appointment, and billing data. Doctors only receive their own related records and do not receive bills.

## Search

`GET /api/search?query=abhi`

Available for Admin and Receptionist. It searches patients by name, patient ID, or phone number. It also searches doctors, appointments, and departments. Search is not case-sensitive.

## Staff and Upload

| API | Method | Who can use it | Purpose |
| --- | --- | --- | --- |
| `/api/staff/receptionists` | GET | Admin | View receptionist accounts |
| `/api/staff/receptionists` | POST | Admin | Create receptionist account |
| `/api/uploads/doctor-photo` | POST | Admin, Doctor | Upload doctor photo |

For photo upload, send a `multipart/form-data` request with the field name `file`. JPG, PNG, and WEBP files up to 5 MB are accepted.

## Common Status Codes

| Code | Meaning |
| --- | --- |
| `200` | Request completed successfully |
| `201` | New record created |
| `400` | Invalid data or business rule failed |
| `401` | Login token is missing or invalid |
| `403` | The logged-in role does not have access |
| `404` | Record was not found |
| `409` | Duplicate username or email |
